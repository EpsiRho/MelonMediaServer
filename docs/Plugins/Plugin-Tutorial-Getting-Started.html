Plugin Tutorial: Getting Started

In this tutorial you'll make a plugin that Melon loads and lists. It doesn't do anything yet, but every plugin starts from this, and the next tutorials build on it.

You'll need:

  • The .NET 10 SDK. Melon runs on .NET 10.
  • Any C# editor. Visual Studio, Rider and VS Code all work.
  • A Melon install. Your plugin references MelonLib.dll from it.

How Plugins Load

When Melon starts it looks through its Plugins folder, loads each .dll, and makes an instance of every class that implements IPlugin. Then, for each plugin, it calls:

  1. LoadMelonCommands(host): hands you IHost, Melon's services.
  2. LoadMelonServerCommands(webApi): hands you IWebApi, the web API hooks.
  3. Execute(): your plugin's start. Start whatever it needs to run here.

When the plugin is disabled, reloaded, or Melon shuts down, it calls Destroy(), where you undo everything Execute() did.

1. Make the Project

A plugin is a normal class library:

dotnet new classlib -n MyFirstMelonPlugin -f net10.0
cd MyFirstMelonPlugin

Then reference MelonLib.dll. It's in the Server folder of your Melon install. Add this to MyFirstMelonPlugin.csproj, changing the path to yours: 

<ItemGroup>
  <Reference Include="MelonLib">
    <HintPath>C:\Users\you\AppData\Local\MelonInstall\Server\MelonLib.dll</HintPath>
    <!-- Melon already has MelonLib loaded, so don't copy it next to your plugin. -->
    <Private>false</Private>
  </Reference>
</ItemGroup>

2. Write the Plugin

Replace Class1.cs with MyPlugin.cs:

using Melon.Interface;

namespace MyFirstMelonPlugin;

public class MyPlugin : IPlugin
{
    // How your plugin shows up in Melon. Name + Authors should be unique,
    // Melon tells plugins apart by them.
    public string Name => "My First Plugin";
    public string Version => "1.0.0";
    public string Authors => "Your Name";     // more than one? separate them with commas
    public string Description => "A simple plugin for Melon.";

    // Melon fills these in for you, right after it loads the plugin.
    public IHost Host { get; set; }
    public IWebApi WebApi { get; set; }

    public void LoadMelonCommands(IHost host) => Host = host;
    public void LoadMelonServerCommands(IWebApi webApi) => WebApi = webApi;

    public int Execute()
    {
        // Start anything your plugin runs here. 0 means it started fine.
        return 0;
    }

    public int Destroy()
    {
        // Stop and clean up whatever Execute started.
        return 0;
    }

    // Launch arguments your plugin reads. These show up in MelonWebApi --help.
    public Dictionary<string, string> GetHelpOptions() => new();
}

IPlugin also has LoadUI and UnloadUI, but they have default implementations, so you can leave them out. Pages in MelonGUI and MelonCLI come from IControllerPlugin instead, which is the next tutorial.

3. Build and Install

dotnet build -c Release

Copy bin/Release/net10.0/MyFirstMelonPlugin.dll into the Plugins folder in Melon's data folder (%LocalAppData%\Melon\Plugins on Windows, ~/.local/share/Melon/Plugins on Linux). Make the folder if it isn't there. Then restart Melon.

Open Plugins in MelonGUI or MelonCLI. "My First Plugin" should be in the list.

It Didn't Show Up

  • Check the .dll is right in Plugins, not in a folder inside it.
  • Check MelonWebLogs.txt in Melon's data folder. If a plugin fails to load, the error is there.
  • If the error is about a missing type or method, your plugin was built against a different MelonLib.dll. Point the reference at the one from the Melon you're running and rebuild.
