Melon Scanner

The scanner is what turns a folder of music files into Melon's library. It walks through your library folders, reads the tags out of every song, and builds the tracks, albums and artists in the database from them. This page explains what happens during a scan, so you know why your library looks the way it does.

Full and Short Scans

A full scan reads every file again. A short scan skips any file that hasn't changed since the last scan (it checks the file's last modified time), so it's much faster when you've only added a few albums. The very first scan is always a full one, since nothing has been read yet.

Only one scan runs at a time. Starting another while one is running does nothing. MelonGUI, MelonCLI, and the Scan endpoints all show its progress.

What a Scan Does

  1. Finds files. It goes through every library folder, and every folder inside those, and counts the files so it can show progress.
  2. Reads tags. For each audio file it reads the title, artists, album, track and disc number, genres, release date, and extra tags like MusicBrainz ids, using ATL. It reads 15 files at a time.
  3. Splits artists and genres. Tags often put several artists or genres in one field. They get split apart on your split indicators (see Configure), so "Artist 1, Artist 2" becomes two artists.
  4. Builds albums and artists. Tracks with the same album name and album artists become one album. Every artist name becomes an artist, and tracks and albums get linked to them.
  5. Matches lyrics. An .lrc file next to a song with the same name becomes that song's lyrics.
  6. Saves everything to the database in big batches.
  7. Removes what's gone. Tracks whose files don't exist anymore are deleted, along with albums and artists left with no tracks.
  8. Updates collections. Every collection runs its filters again, so new songs show up in them. See Collections.

Supported Files

.mp3, .flac, .m4a, .aac, .ogg, .wav and .wma, plus .lrc for lyrics. Anything else is ignored.

When a File Fails

If a file can't be read (a broken file, or tags ATL doesn't understand), the scan keeps going and the file and its error are saved to the FailedFiles collection in MongoDB (see FailedFile). There's no page for these in the controllers yet, so check that collection when a song is missing from your library.

Resetting the Database

Reset database (in Database, in MelonGUI or MelonCLI) throws the whole library away so you can scan from nothing. It deletes all tracks, albums, artists, playlists, collections, queues, stats and failed files, and the artwork saved for them.

User accounts are kept, with their usernames, passwords and profiles. But everything they did in the library, like plays, skips and ratings, is gone. There's no undo, so make a backup first.
