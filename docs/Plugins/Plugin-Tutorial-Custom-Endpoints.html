Plugin Tutorial: Custom Endpoints

Plugins can add their own API endpoints, replace Melon's, or just run some code whenever an endpoint is called. All of that goes through WebApi, the IWebApi Melon gave your plugin when it loaded.

There are two ways in:

  • Middleware runs before Melon handles a request. Return something and that's the response. Return null and Melon carries on like normal.
  • Events fire after Melon handled a request, right before the response goes out. They can't change the response, they just let you know it happened.

1. Add an Endpoint

Middleware is a function that gets every request and returns bytes or null. This one answers /api/myplugin/info and ignores everything else: 

using System.Text;
using Melon.Models;

private byte[]? InfoEndpoint(WebApiEventArgs args)
{
    // args.Api is the request path.
    if (args.Api != "/api/myplugin/info") return null; // not ours, let Melon handle it

    return Encoding.UTF8.GetBytes($"{Name} {Version} by {Authors}");
}

Register it in Execute, and remove it in Destroy. The string is just a name for it:

public int Execute()
{
    WebApi.UsePluginMiddleware(new("MyPlugin.Info", InfoEndpoint));
    return 0;
}

public int Destroy()
{
    WebApi.RemovePluginMiddleware("MyPlugin.Info");
    return 0;
}

Middleware only runs for signed-in requests, so you have to send a token to try it (see Authorization for how to get one): 

curl http://localhost:14524/api/myplugin/info -H "Authorization: Bearer <token>"

2. Reading the Request

WebApiEventArgs tells you who's asking and what they sent:

PropertyWhat it is
ApiThe request path, like /api/myplugin/info.
UserThe user's id.
RoleTheir role: Admin, User or Pass.
ArgsThe query string. Each value is a string[], since a key can show up more than once.
 
// /api/myplugin/hello?name=Epsi
if (args.Api == "/api/myplugin/hello" && args.Args.TryGetValue("name", out var value))
{
    var name = ((string[])value)[0];
    return Encoding.UTF8.GetBytes($"Hello, {name}!");
}

Passwords and tokens are taken out of Args before your plugin sees them. Check Role yourself if an endpoint should be admin only.

3. Replace an Endpoint

Since middleware runs first, answering one of Melon's own paths replaces it. This makes /api/track return your text instead of the track: 

private byte[]? OverrideTrack(WebApiEventArgs args)
{
    if (args.Api != "/api/track") return null;
    return Encoding.UTF8.GetBytes("This is a custom response from My First Plugin.");
}

Be careful with this. Every client expects Melon's endpoints to answer in their usual shape, and if yours doesn't, they break. Only take over the requests you actually need to, and return null for the rest.

4. Listen for Events

If you only want to know something happened, use an event instead. Every endpoint has one on WebApi (the full list is on IWebApi): 

public int Execute()
{
    WebApi.GetTrack += OnGetTrack;
    return 0;
}

public int Destroy()
{
    WebApi.GetTrack -= OnGetTrack; // always unhook, or you get called after you're disabled
    return 0;
}

private void OnGetTrack(object? sender, WebApiEventArgs args)
{
    Console.WriteLine($"Track requested by user {args.User}, status {args.StatusCode}");
}

Events also get StatusCode and Message, what Melon answered with. See WebApiEventArgs.
