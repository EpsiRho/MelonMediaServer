Installation

Melon releases come with everything they need to run, so you don't need .NET installed. The one thing Melon needs from you is a database.

MongoDB

Melon keeps your library in MongoDB.

  • Windows: skip this. MelonGUI's setup can install a MongoDB service just for Melon, with a password on it. If you already run MongoDB you can point Melon at that instead.
  • Linux / macOS: install MongoDB first, using MongoDB's Linux or macOS guide.

Install Melon

Go to the Download page and click Install Latest. That downloads MelonInstaller for your system. Run it, pick a branch (if there's more than one) and a folder, and it downloads and unzips the latest release for you.

You can also skip the questions by passing the answers in:

MelonInstaller -branch Beta -installPath "C:\Melon"

Already have a release zip? Use -localPath <zip> and it installs from that instead of downloading.

When it's done the installer opens a controller for you. If you double-clicked it, that's MelonGUI. If you ran it from a terminal, MelonCLI starts right there in the same terminal. Add -noLaunch if you don't want either.

What gets installed

FolderWhat it is
ServerMelonWebApi, the server itself.
ControllerMelonGUI, the Windows app for setting up and running the server. Windows only.
CLIMelonCLI, the same thing in a terminal. Works everywhere.
InstallerMelonInstaller, kept around for updates and switching branches.

By default this all goes in %LocalAppData%\MelonInstall on Windows and ~/.local/share/MelonInstall on Linux.

First Time Setup

MelonGUI or MelonCLI starts the server and walks you through setup. You'll make your admin account, connect Melon to MongoDB, and add the folders your music lives in.

Then start a scan. Nothing shows up in your library until a scan has finished. There's a Full scan and a Short scan, but on the first run they both end up doing a full scan, since Short only skips files that haven't changed since the last one.

Letting Other Devices Connect

Out of the box Melon listens on http://localhost:14524, which means only the computer it's running on can reach it. That's on purpose: you choose how it gets exposed. There are two ways to do it.

Recommended: Caddy

Caddy is a small web server that sits in front of Melon. It gets an HTTPS certificate for you from Let's Encrypt and renews it on its own, so you never have to think about certs again. Melon stays on localhost and only Caddy talks to it.

What you need:

  • A domain name (or a free subdomain from something like Duck DNS) pointed at your public IP.
  • Ports 80 and 443 forwarded on your router to the computer running Melon. Caddy needs both to get its certificate.

Install Caddy, then make a file called Caddyfile with this in it: 

# Your domain. Caddy gets the certificate for this name.
music.example.com {
    # Send everything to Melon. WebSockets (casting) work through this too.
    reverse_proxy localhost:14524
}

Then run Caddy from the same folder:

caddy run

That's it. Clients connect to https://music.example.com. Once it works, set Caddy up to start with your computer: Caddy's Running Caddy page shows how on each OS.

Leave Melon's listening URL alone for this, and don't forward port 14524. Caddy is the only thing that should be reachable from outside.

Optional: your own certificate

If you'd rather not run Caddy, Melon can serve HTTPS itself with a certificate you give it. You'll need the certificate as a .pfx (or .p12) file. You can get one from Certbot and convert it with openssl pkcs12 -export.

  1. Open Networking in MelonGUI or MelonCLI.
  2. Pick Apply HTTPS, choose your .pfx file, enter its password, and pick a port.
  3. Restart Melon when it asks.
  4. Forward that port on your router.

Certificates expire, and you have to renew this one yourself. Melon warns you on startup and on the Networking page when it has expired. Disable HTTPS on the same page goes back to plain HTTP.

Just want other devices on your home network to connect, no HTTPS? Change the listening URL in Networking to http://*:14524. Don't forward that to the internet.

See Configure for every other setting.

Updating

Melon checks GitHub for newer releases on its branch. You can update from MelonGUI, MelonCLI, or a client, or run the installer yourself: 

MelonInstaller -update -restart -installPath "C:\Melon"

To switch branches, run the installer with -branch. See Branches.
