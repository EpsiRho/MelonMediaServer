VisualsController Documentation

The VisualsController gives clients pre-computed data for driving visualizations, so they don't have to analyse audio live. That saves a lot of battery on phones and watches. It serves:

  • Waveforms: amplitude points for seek bars.
  • FFTVIS frames (.fvz): per-frame frequency band levels for bar visualizers, mesh shaders and similar effects. See FFTVIS for the format and decoders (C#, JavaScript).
  • Beat times: the beat grid, downbeats and per-beat band energy, plus individual kick/snare/hat hits. Good for album-art pulses and haptics.
  • Moments: stretches to react to, such as soft passages, energetic sections, builds and drops.

Nothing is generated during scans. Files are made the first time a client asks for them, then kept in an LRU cache ({data}/Cache/Visuals) whose size admins set. Generation takes about 0.3–2 seconds for frames and 2–4 seconds for beat/moment analysis per track. Clients should prefetch the next few tracks in their queue so data is ready before playback starts.

The server admin can turn visualizations off entirely. When they are off, the data endpoints return 403.

Controller Route: /api/visuals

All routes within the VisualsController are prefixed by /api/visuals/. Data routes accept media tokens in the same way as /api/download and /api/stream.

Summary of Endpoints

Endpoint Method Description Authorization
/api/visuals/settings GET Whether visuals are on, the default format and the client limits. Admin, User
/api/visuals/settings POST Change visual settings. Admin
/api/visuals/status GET Settings plus cache usage and running jobs. Admin
/api/visuals/cache DELETE Clear the visuals cache. Admin
/api/visuals/waveform GET A track's waveform at a given width. Admin, User
/api/visuals/fvz GET A track's FFTVIS frequency frames, in the server default or a requested format. Admin, User
/api/visuals/beat-times GET A track's beats, downbeats and drum hits. Admin, User

Visual Format

An .fvz file's format is described by these fields. The server has a default for each. A client can override any of them per request, for example 16 bands at 30 fps for a watch, or 256 bands at 120 fps for a TV. Requested values are clamped to the admin's limits.

Field Default Description
bands64Number of frequency bands (bars).
fps60Frames per second. Lower rates with client-side interpolation make much smaller files.
fftResolution4096FFT window size, rounded to a power of two. Larger sizes resolve bass better but smear fast changes.
mappingNormalizedHow FFT bins map to bands: Normalized, Mel or Log10.
dbFloor-80Level (dB) shown as zero.
dbRange90dB range from the floor up to full scale.
frequencyMin20Lowest frequency (Hz).
frequencyMax20000Highest frequency (Hz).
smoothness0Smoothing across neighbouring bands.
stereofalseStore left and right channels separately.
quantizeBits8Bits per value (4–16). 8 is plenty for display. Fewer bits make smaller files.
decayPerSecond0Bar fall rate baked in at encode time. 0 = off. 1.5–3 looks natural and compresses better.
codecBrotliBrotli, Zstd or None.

Limits (admin-set) bound bands, fps, fftResolution and quantizeBits, and can disallow stereo. Out-of-range values are clamped rather than rejected. The decoded file's header always reports the format that was actually produced.

Get Settings

Returns what a client needs in order to choose a format.

Details:

  • Endpoint: /api/visuals/settings
  • Method: GET
  • Authorization: JWT with Admin or User role

Example Response:

{
  "enabled": true,
  "defaults": { "bands": 64, "fps": 60, "fftResolution": 4096, "mapping": "Normalized", "dbFloor": -80, "dbRange": 90,
                "frequencyMin": 20, "frequencyMax": 20000, "smoothness": 0, "stereo": false, "quantizeBits": 8,
                "decayPerSecond": 0, "codec": "Brotli" },
  "limits": { "minBands": 4, "maxBands": 256, "minFps": 10, "maxFps": 240, "minFftResolution": 1024,
              "maxFftResolution": 16384, "minQuantizeBits": 4, "maxQuantizeBits": 16, "allowStereo": true }
}

Set Settings

Replaces the visual settings. Limits are applied first, then the default format, which must sit within those limits.

Details:

  • Endpoint: /api/visuals/settings
  • Method: POST
  • Authorization: JWT with Admin role

Body (JSON):

  • enabled (bool)
  • defaults (Visual Format)
  • limits (Limits)
  • cacheMegabytes (int, 64–102400): Cache size. The oldest-used files are removed when the cache is full.
  • maxConcurrentJobs (int, 1–16): How many tracks are analysed at once.

Responses:

  • 200 OK: Returns the saved settings.
  • 400 Bad Request: A value is invalid or the defaults fall outside the limits.

Get Status

Returns the full settings plus cacheBytes, cacheFiles and running (jobs in progress).

  • Endpoint: /api/visuals/status
  • Method: GET
  • Authorization: JWT with Admin role

Clear Cache

Deletes every cached visual file. Returns { "freedBytes": 123456 }.

  • Endpoint: /api/visuals/cache
  • Method: DELETE
  • Authorization: JWT with Admin role

Waveform

Returns a float array of amplitude points, one per pixel of the requested width. This replaces /api/download/track-wave, which still works but is deprecated. The waveform endpoint works even when visualizations are turned off.

  • Endpoint: /api/visuals/waveform
  • Method: GET
  • Authorization: JWT with Admin or User role

Parameters:

  • id (string, required): The track ID.
  • width (float, required, 1–100000): Number of points.

Responses:

  • 200 OK: Float array.
  • 400 Bad Request: Width missing or out of range.
  • 404 Not Found: Track not found.
curl "https://your-melon-server.com/api/visuals/waveform?id=66bc9aadab7ba419497e6a97&width=500" \
     -H "Authorization: Bearer <User-JWT>"

FFTVIS Frames

Returns the track's .fvz file (application/x-fvz, FFTVIS v3). If the file isn't cached in this format yet, it's generated before responding. Responses carry an ETag and are cacheable by the client for a day.

  • Endpoint: /api/visuals/fvz
  • Method: GET
  • Authorization: JWT with Admin or User role

Parameters:

  • id (string, required): The track ID.
  • Any Visual Format field (optional): Overrides the server default.

Responses:

  • 200 OK: The .fvz bytes.
  • 400 Bad Request: An unknown mapping or codec.
  • 403 Forbidden: Visualizations are turned off.
  • 404 Not Found: Track not found.
  • 500: The track couldn't be decoded.
# A watch-friendly file: 16 bands, 30 fps, 6-bit, with bar fall-off baked in
curl "https://your-melon-server.com/api/visuals/fvz?id=66bc9aadab7ba419497e6a97&bands=16&fps=30&quantizeBits=6&decayPerSecond=2" \
     -H "Authorization: Bearer <User-JWT>" -o track.fvz

Decode with FFTVIS.AudioDecoder.Decode(stream) in C#, or fvzDecoder.js in JavaScript. Then call GetFrameFromTime(positionMs) (or frameAt in JS), which interpolates between frames, so low frame rates still animate smoothly.

Beat Times

Returns the beat grid and drum hits for a track. Arrays are parallel ("struct of arrays") to keep the JSON small: beats.time[i], beats.downbeat[i], beats.strength[i] and so on all describe beat i.

  • Endpoint: /api/visuals/beat-times
  • Method: GET
  • Authorization: JWT with Admin or User role

Parameters: id (string, required).

Fields:

  • bpm: Tempo.
  • rhythm: How confident the tempo is.
    • pulse: A clear beat.
    • uncertain: Use the beats lightly.
    • noPulse: The beats aren't meaningful. Fall back to hits or the energy curve.
  • downbeatConfidence, beatsPerBar
  • beats: Per-beat data.
    • time (seconds), downbeat
    • strength (0–1)
    • sharpness (0–1): How much of the beat is in the high bands. Low means a soft thump, high means a crisp click. Useful for choosing haptic styles.
    • low, lowMid, highMid, high: Band energy at the beat (0–1, normalized per track).
  • hits: Individual drum onsets: time, kind (kick, snare or hat) and strength.
{
  "version": 1, "trackId": "66bc9aadab7ba419497e6a97", "duration": 243.1,
  "bpm": 124.0, "rhythm": "pulse", "downbeatConfidence": 0.82, "beatsPerBar": 4,
  "beats": { "time": [0.48, 0.97, 1.45], "downbeat": [true, false, false], "strength": [0.9, 0.6, 0.7],
             "sharpness": [0.2, 0.5, 0.3], "low": [1.0, 0.4, 0.8], "lowMid": [0.5, 0.3, 0.4],
             "highMid": [0.3, 0.6, 0.3], "high": [0.2, 0.5, 0.2] },
  "hits": { "time": [0.48, 0.97], "kind": ["kick", "snare"], "strength": [0.95, 0.7] }
}

Moments

Returns a smoothed energy curve and a list of moments to react to, such as dimming the visuals in a piano interlude or bursting on a drop.

  • Endpoint: /api/visuals/moments
  • Method: GET
  • Authorization: JWT with Admin or User role

Parameters: id (string, required).

Fields:

  • hop: Seconds between curve samples (1.0).
  • energy: Per-sample energy (0–1), relative to the track's own loud parts.
  • pulse: Per-sample beat clarity (0–1).
  • items: Moments, each with kind, start, end (seconds) and intensity (0–1). Moments can overlap. For example, a peak sits inside an energetic stretch, and a build ends where a drop starts.
    KindMeaning
    softQuiet, sparse passage (≥ 6 s): piano, vocal solo, ambient pad.
    energeticLoud, busy section (≥ 6 s).
    peakThe most intense energetic section of the track.
    buildEnergy rising steadily over 4–20 s.
    dropA sudden jump in energy and bass, snapped to a beat. start is the hit.
    beatlessNo clear pulse (≥ 8 s).
    silenceNear-silent (≥ 2 s), such as gaps and hidden-track pauses.
  • sections: Structural boundaries (start, end), such as verse and chorus changes.
{
  "version": 1, "trackId": "66bc9aadab7ba419497e6a97", "duration": 243.1, "hop": 1.0,
  "energy": [0.12, 0.15, 0.2], "pulse": [0.1, 0.1, 0.3],
  "items": [
    { "kind": "soft", "start": 0.0, "end": 31.0, "intensity": 0.8 },
    { "kind": "build", "start": 31.0, "end": 46.4, "intensity": 0.6 },
    { "kind": "drop", "start": 46.4, "end": 47.4, "intensity": 0.9 },
    { "kind": "energetic", "start": 47.0, "end": 110.0, "intensity": 0.85 }
  ],
  "sections": [ { "start": 0.0, "end": 31.0 }, { "start": 31.0, "end": 78.5 } ]
}

Prefetch

Queues generation for upcoming tracks in the background and returns immediately. Send the next few tracks in the play queue, with the same format you'll request later, so the files are already cached by the time each track starts.

  • Endpoint: /api/visuals/prefetch
  • Method: POST
  • Authorization: JWT with Admin or User role

Body (JSON):

  • ids (string[], required, at most 8): Track IDs.
  • include (string[], optional): Any of fvz, beat-times and moments. All three by default.
  • format (Visual Format, optional): Fields to override for the .fvz files.

Responses:

  • 202 Accepted: { "queued": 3, "notFound": [] }
  • 400 Bad Request: Missing IDs, too many IDs, an unknown include, or a bad format.
  • 403 Forbidden: Visualizations are turned off.
curl -X POST "https://your-melon-server.com/api/visuals/prefetch" \
     -H "Authorization: Bearer <User-JWT>" -H "Content-Type: application/json" \
     -d '{ "ids": ["66bc9aadab7ba419497e6a98", "66bc9aadab7ba419497e6a99"], "format": { "bands": 32, "fps": 30 } }'
