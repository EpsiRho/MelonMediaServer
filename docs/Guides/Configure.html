Configure Melon

You change Melon's settings from MelonGUI or MelonCLI. Both have the same sections, in the same order, so this guide works for either one. Most settings can also be changed by an admin over the API; those endpoints are under Settings.

Library

  • Library scan: start a scan. A normal scan skips files that haven't changed since the last one; a full scan reads everything again. See Melon Scanner.
  • Library folders: the folders Melon looks in for music.
  • Metadata: the split indicators. Tags often cram several artists or genres into one field, like artist 1, artist 2; artist 3 // artist 4. These are the separators Melon splits them on.
  • Artwork: where Melon gets artist pictures and banners from, in what order, and their API keys. See Artwork.
  • Visuals: the default format for the visualizer data clients can ask for, limits on what they can ask for, and the cache.

Database

  • Connection: where your MongoDB is. On Windows, Set up MongoDB installs one just for Melon.
  • Backups: back up the database to Exports/DbBackups in Melon's data folder, or load one back. Backups are quick even with a big library.
  • Transfer: import playlists and collections (m3u, pls, or xml), or export one.
  • Queue cleanup: queues are deleted after this many hours (48 by default) unless they're favorited. Set it to -1 to keep them forever.
  • Reset database: wipes everything except user accounts. Plays, ratings, playlists and so on are all gone after this, so make a backup first.

Networking

  • Listening URL: the address and port Melon listens on. It's http://localhost:14524 by default, so only the same computer can connect. * means any address, like http://*:14524.
  • HTTPS: use your own certificate. The Installation guide covers this, and the easier way with Caddy.

Users

Make invite codes, see who's on your server, and sign everyone out of every device. See Users.

Stats

Server wide listening stats: plays, top tracks, and what people listen to when.

Plugins

Turn plugins on and off, open their pages, rescan the Plugins folder for new ones, or reload all of them. See Plugins.

System

  • Preferences: the language. Melon has English and Spanish. To add one, copy the English strings file and translate it.
  • Open data folder: where Melon keeps its configs, backups, plugins and log.
  • Updates: check GitHub for a newer release on your branch, read its changelog, and install it. Melon restarts itself after.
  • Server: restart or stop Melon.

Launch Arguments

You can pass these to MelonWebApi when you start it. Plugins can add their own, so run MelonWebApi --help to see everything your install supports.

ArgumentWhat it does
--helpLists every launch argument.
--version, -vPrints Melon's version.
--disablePlugins, -dStarts without loading any plugins. Good for checking if a plugin is what's breaking things.
--lang <code>, -lUses this language instead of the one in settings, like --lang ES.
--allowConversion, -cWhen a Melon update changes how something is stored, back it up and convert it without asking. You need this when nobody's there to answer.
--dataPath <folder>Keeps Melon's data somewhere other than the default folder.

Flags

Configs/MelonFlags.json has a switch for troubleshooting. Set DisablePlugins to true and Melon never loads plugins, the same as always passing --disablePlugins.
