WebSockets

Clients keep a WebSocket open to Melon so the server can talk to them without being asked. That's how one device controls another (your phone playing and pausing music on your PC), how clients find out a queue changed, and how they can get live scan progress.

Connect to /api/stream/connect with your token. Every message, both ways, is plain text. Each connected client is a WSS on the server.

Staying Connected

If Melon hasn't heard anything from a client for 2 minutes, it sends PING. Reply with PONG. If it still hasn't heard anything after 3 minutes, it closes the connection. Any message counts, so a client that's busy talking never gets pinged.

Messages You Send

MessageWhat it does
SET DEVICE:Epsi's Phone Names this device. A device without a name can't be found or controlled, so send this right after connecting. Melon replies with the name, or Device Name Taken if another device of yours already has it.
SET PUBLIC:true Lets this device show up in the Stream endpoints so it can be controlled. Replies DEVICE IS PUBLIC:true.
SET QUEUE:<queue id> Tells Melon which queue you're playing. Send it every time you switch queues. Replies with the id.
GET QUEUE Replies with the queue id Melon thinks you're playing.
SET STATE:<json> Your playback state (what's playing, position, paused, whatever your client wants to share). Melon passes it on to every device watching you.
WATCH DEVICE:<name> Start getting another device's state, as DEVICE STATE:<json>. Use this when you're controlling it. Replies WATCH DENIED if you can't see that device.
UNWATCH DEVICE Stop watching.
SEND PROGRESS Start getting scan progress about every 100ms, as PROGRESS:<scanned>:<found>, plus PROGRESS INFO:<status> when the status changes and END PROGRESS when it's done. Nicer than calling api/scan/progress over and over.
STOP PROGRESS Stop the progress messages.

A message Melon can't make sense of gets Invalid Syntax back.

Messages You Get

Other devices control you by calling the Stream endpoints, and Melon passes the command down your WebSocket:

MessageWhat your client should do
PLAY QUEUE:<queue id>Play that queue. If it's the one already playing, just resume.
PAUSEPause.
SKIPGo to the next song.
REWINDGo back. It's up to you whether that restarts the song first, like most players do.
VOLUME:20Set the volume to 20.
UPDATE QUEUEThe queue you're playing changed through the API. Load it again.
WATCHERS:2How many devices are watching you right now. Handy for showing "being controlled".
