Plugin Tutorial: Controller Page

Now let's give the plugin from Getting Started its own page in MelonGUI and MelonCLI. You don't write any UI for this. You describe the page as a list of fields and buttons, and both controllers draw it for you. When someone presses a button, Melon calls your plugin on the server with whatever they typed in.

1. Add IControllerPlugin

Add IControllerPlugin next to IPlugin and implement its two methods:

using System.Text.Json;
using Melon.Interface;

public class MyPlugin : IPlugin, IControllerPlugin
{
    // ... everything from Getting Started ...

    // What the page looks like: the fields, then the buttons.
    public PluginPage GetPage() => new(
        [
            //  key     label         type       starting value
            new("name", "Your name",  "text",    "Melon"),
            new("loud", "Shout it",   "boolean", false),
        ],
        [
            //  key      button text
            new("greet", "Say hello"),
        ]);

    // Called when a button is pressed. values has every field, by key.
    public object? Invoke(string action, JsonElement values)
    {
        if (action != "greet") throw new ArgumentException("Unknown action.");

        var text = $"Hello, {values.GetProperty("name").GetString()}!";
        if (values.GetProperty("loud").GetBoolean()) text = text.ToUpper();

        return text; // a string shows up as a message
    }
}

2. How It Works

GetPage returns a PluginPage, which is just two lists. Each PluginField is a key (how you read it back), a label (what people see), a type, and a starting value. Each PluginAction is a key and the text on its button.

These are the field types the controllers know how to draw:

TypeShows asValue you get back
textText boxstring
booleanTogglebool
numberNumber boxnumber
argbColor pickerint, from Color.ToArgb()

What you return from Invoke decides what happens next:

  • Return a string and the controller shows it as a message.
  • Return a new PluginPage and the page redraws with it. Handy after saving, or to show different fields.
  • Throw an ArgumentException and its message shows as an error.

Invoke runs on the server, not in the controller, so it can use everything in Host, including Host.Administration. Keep it quick though. Long running work belongs in something you start from Execute.

3. Try It

Rebuild, copy the .dll into Plugins again, and restart Melon. Open Plugins in MelonGUI or MelonCLI, pick your plugin, and press Say hello. The page only shows while your plugin is enabled.

4. Launch Arguments

Some things are better as a launch argument than a button, like a reset switch. List yours in GetHelpOptions so they show up in MelonWebApi --help: 

public Dictionary<string, string> GetHelpOptions() => new()
{
    { "--resetMyPlugin", "Resets My First Plugin's settings." }
};

Then check for it in Execute. Host.StateManager.LaunchArgs has every argument Melon started with, without the leading dashes: 

if (Host.StateManager.LaunchArgs.ContainsKey("resetMyPlugin"))
{
    // reset here
}

Next up, the page forgets what you typed as soon as Melon restarts. Managing Settings fixes that.
